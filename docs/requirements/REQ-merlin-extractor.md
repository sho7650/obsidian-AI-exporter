# REQ: Merlin Extractor - Requirements Specification

## 1. Background & Goal

Add **Merlin AI** (`www.getmerlin.in`) as a supported platform. Besides the conversation text,
the export must include:

- **Generated images** — saved as external files, same mechanism as Gemini/ChatGPT
  ([ADR-008](../adr/008-image-sync-strategy.md), [ADR-041](../adr/041-chatgpt-generated-image-capture.md)).
- **Artifacts ("crafts")** — files generated by Merlin (`.html`, `.md`, `.mmd`, …), saved as
  external files next to the images.

## 2. Scope

Requirements only. Architecture/implementation are deferred to the design phase.

Out of scope:

- Pages other than `/chat/{uuid}` (Projects, shared chats, …).
- Agent progress steps (see §3.6).
- Attachments uploaded by the user in their messages (decision Q17).
- Hosts other than `www.getmerlin.in`

## 3. DOM Structure Analysis (verified live on 2026-11-24)

Verified on three conversations via the shared browser:

| Conversation                                 | Content                                                                                              |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `/chat/ed96096b-c79b-46ee-bf25-83df2cad6093` | HTML craft + 3 generated images (GPT Image, Seedream)                                                |
| `/chat/97cfdf53-b50a-4a78-aa4d-6e4291b603a3` | Crafts `.md`, `.mmd`, `.mmd` (no images)                                                             |
| `/chat/9dc30134-3009-46cb-a190-82b46c9c25c6` | Plain text + inline code blocks (no crafts)                                                          |
| `/chat/af5dd0aa-eaf8-4292-84d3-79010e97ab8e` | Long conversation: 32 messages, 140 code blocks (bash/apache/sql), h2–h4, lists, inline code, `<hr>` |
| `/chat/8013b90c-0da9-433e-993b-775ad0f8aa80` | 14 messages, 1 table, 11 display formulas (KaTeX)                                                    |
| `/chat/776397b1-e100-44c7-a1bd-20f72ca9f76b` | Project chat ("Test"); explicit models; inline formulas; web-search citations; response versions     |

Merlin is a React/Next.js app (Tailwind, Radix UI, Streamdown markdown renderer).

### 3.1 Conversation container

```
div.chat-messages-area
  ├── article[data-message-id]   ← user
  ├── article[data-message-id]   ← assistant
  └── …
```

- Every message (user and assistant) is an `<article>` with `data-message-id` = UUID.
- Messages alternate user/assistant. All messages except the **last turn** are direct children
  of `.chat-messages-area`; the last user/assistant pair is nested in a wrapper
  (`.chat-messages-area > div.mb-[calc(var(--promptarea-height)…)] > div > article`), both on
  page load and after a new response (verified on two conversations and after reload).
  Messages must therefore be queried as descendants (`article[data-message-id]` in document
  order), not as direct children.
- **No virtualization**: on the long sample (32 messages, scroll height ~66 000 px) all 32
  articles were in the DOM from page load with non-empty bodies, and the set of message ids did
  not change while scrolling to the top and back to the bottom. No "load earlier" element exists
  before the first article. No scroll-harvesting is required.

### 3.2 User message

```html
<article class="group/message ml-auto grid max-w-[80%] …" data-message-id="…">
  <div class="grid gap-1.5">
    <div class="ml-auto grid w-fit gap-1.5 rounded-3xl bg-secondary …">
      <div class="max-w-full …">
        <p class="whitespace-pre-wrap my-0.5"><span>text</span></p>
      </div>
    </div>
    <div class="z-10 flex …">  ← hover toolbar (copy, …) — exclude
  </div>
</article>
```

- Role discrimination: user article has class `ml-auto`; the assistant article has a header
  (model icon + label) and no `ml-auto`. The label is "Merlin" or the chosen model name
  (§3.10), so it must not be used for role detection. The discriminator must not rely on class
  alone if a more stable signal is found during design.
- Text: `p.whitespace-pre-wrap` (multi-line preserved).

### 3.3 Assistant message

```html
<article class="group/message grid transform-none gap-3 …" data-message-id="…">
  <div class="flex items-center justify-between gap-2">            ← header
    <span><img alt="merlin ai model's icon"> <button aria-expanded>Merlin ›</button></span>
  </div>
  <div class="grid gap-1.5">
    <div>
      <div>
        <div class="… chat-reply-markdown …"></div>                 ← may be empty
        <div class="… chat-reply-markdown …">                       ← response body
          <div class="space-y-4 …"> p / h2 / ul / ol / code-block / image … </div>
        </div>
      </div>
      <div class="mt-2 grid …"> craft cards </div>                  ← optional (§3.5)
    </div>
    <div class="z-10 flex …"> copy / regenerate / thumbs / credits </div>  ← exclude
  </div>
</article>
```

- Body: the **non-empty** `.chat-reply-markdown` elements (observed 1–3 per message, some empty).
- Markdown elements carry `data-streamdown` attributes (`strong`, `heading-2`,
  `ordered-list`, `unordered-list`, `list-item`, `code-block`, …).
- Exclude: header (model icon, "Merlin"/model label), action toolbar, credit counter (e.g. "71"),
  sponsored box (§3.8).

### 3.4 Generated images

```html
<div class="not-prose flex gap-2">
  <div class="group relative …">
    <button aria-haspopup="dialog">
      <img alt="<descrizione>" loading="lazy"
           src="https://storage.googleapis.com/dall-e-images/<uid>%2F<uuid>.png">
    </button>
    <div …> copy / download / bookmark buttons </div>
  </div>
</div>
<p><span data-streamdown="strong">Generato con GPT Image 2.5 Medium</span></p>
<p>Ecco il diagramma in formato PNG.</p>
```

- Located inside `.chat-reply-markdown` → `div.not-prose` → `button > img`.
- Source host: `storage.googleapis.com` (cross-origin). Observed for both GPT Image and Seedream.
- **Readability verified**: `fetch(src, {mode:'cors'})` from the page returned `200`,
  `image/png`, ~1.1 MB. Natural size observed 1024×1536.
- `alt` contains a meaningful description → use as image alt text.
- The model icon `img[alt$=" ai model's icon"]` (cdn.jsdelivr.net; e.g. `merlin ai model's icon`,
  `gpt-6-luna ai model's icon`) must **not** be exported.
- Each image is followed by a `<p>` with a single bold "Generato con <model>" line → **must be
  removed** from the output (decision Q6). The exact matching rule (text prefix vs. position)
  is a design decision; it must not remove other bold paragraphs.

### 3.5 Artifacts ("crafts")

In the chat the craft is only a **card**; its content is not in the message DOM.

```html
<div class="mt-2 grid grid-cols-[repeat(auto-fill,minmax(220px,1fr))] gap-2">
  <button>
    <div …>
      <div …><svg class="lucide lucide-code …"></div>
      <div …>
        <div class="line-clamp-2 …">handshake-http.html</div>     ← file name
        <p class="text-left text-muted-foreground">Click to open craft</p>  ← "Showing craft" when open
      </div>
    </div>
  </button>
</div>
```

Clicking the card opens a side panel (outside the `article`):

```
panel header: <span class="text-base font-semibold …">handshake-http.html</span>
[role=tablist]  tabs: "Code" | "Preview" (default) | "Edit"
[role=tabpanel] Preview → <iframe src="https://crafts.getmerlin.in/render"> (cross-origin, not readable)
[role=tabpanel] Code    → code-block (Streamdown)
    [data-language="html|markdown|mermaid"]
    button[title="Download file"], button[title="Copy Code"]
    <code>
      <span class="block before:content-[counter(line)] …">…line 1…</span>
      <span class="block …">…line 2…</span>
    </code>
```

Findings:

- Source is in the main-document DOM **only** after: click card → panel opens → click "Code" tab.
- `code.textContent` **loses newlines** (e.g. mermaid became `flowchart TD    A[...]`). The source
  must be rebuilt by joining each `code > span.block` text with `\n` (verified correct).
- Line numbers are CSS `::before` content → not part of the text (correct).
- Observed types: `.html` (`data-language="html"`), `.md` (`markdown`), `.mmd` (`mermaid`).
- No JSON API returning craft content was found among page requests (only RSC/DOM).
- The Preview iframe (`crafts.getmerlin.in`) is cross-origin and must not be used.

### 3.6 Agent steps (excluded)

The `Merlin ›` header button (`aria-expanded`) expands a timeline of `h3 > button` steps
(e.g. "Merlin Magic", "Saving handshake-http.html", "Presenting handshake-http.html").
**Not exported** (decision Q4). Extraction must work regardless of expanded/collapsed state and
must not include these steps if the user has expanded them.

### 3.7 Inline code blocks (stay inline)

```html
<div data-streamdown="code-block" data-language="text|typescript|…">
  <div data-streamdown="code-block-header"><span>text</span></div>
  <div …><div data-streamdown="code-block-actions"> download / copy </div></div>
  <div data-streamdown="code-block-body" data-language="…">
    <pre class="language-…"><code><span class="block …">line</span>…</code></pre>
  </div>
</div>
```

- Remain in the note as fenced Markdown code blocks with the language from `data-language`
  (decision Q8). Header/actions must be excluded; lines rebuilt per `span.block` (same
  newline issue as §3.5).
- **`content-visibility: auto`**: every `[data-streamdown="code-block"]` has
  `style="content-visibility: auto; …"`. For blocks outside the viewport, **`innerText` returns
  an empty string** (verified: 139 off-screen blocks, `innerText.length === 0`), while
  `textContent` is intact. Extraction must be DOM-based (`textContent` per `code > span.block`,
  or the HTML→Markdown pipeline), **never `innerText`**, and must not depend on scroll position.
- Other Streamdown elements observed in the long sample: `heading-2/3/4`, `inline-code`,
  `horizontal-rule`, `ordered-list`, `unordered-list`, `list-item`, `strong`. Languages seen:
  `bash`, `apache`, `sql`, `text`, `typescript`.

### 3.9 Tables and math formulas

Verified on `/chat/8013b90c-…`.

**Tables** (Streamdown):

```html
<div class="my-4 flex flex-col gap-2 rounded-lg border …" data-streamdown="table-wrapper">
  <div class="flex items-center justify-end gap-1">        ← actions — exclude
    <button title="Copy table">…</button><button title="Download table">…</button>
    <button title="View fullscreen">…</button>
  </div>
  <div class="border-collapse overflow-x-auto …">
    <table data-streamdown="table">
      <thead data-streamdown="table-header">
        <tr data-streamdown="table-row">
          <th data-streamdown="table-header-cell">Pezzo</th>
          <th data-streamdown="table-header-cell" style="text-align: right;">Dimensione lungo Y</th>
        </tr>
      </thead>
      <tbody data-streamdown="table-body">
        <tr data-streamdown="table-row"><td data-streamdown="table-cell">1</td>…</tr>
      </tbody>
    </table>
  </div>
</div>
```

- Standard `<table>/<thead>/<tbody>/<th>/<td>` → convertible to a GFM table.
- Column alignment is only in inline `style="text-align: right"` on `th`/`td` (observed:
  `none, right, right`).
- The actions toolbar (Copy / Download / View fullscreen) must be excluded.
- Tables are **not** under `content-visibility` (only code blocks are).

**Math** (standard KaTeX):

```html
<span class="katex-display">
  <span class="katex">
    <span class="katex-mathml">
      <math display="block"><semantics>…
        <annotation encoding="application/x-tex">\frac{20}{2} + \frac{10}{2} = 15 \text{ mm}</annotation>
      </semantics></math>
    </span>
    <span class="katex-html" aria-hidden="true">…</span>
  </span>
</span>
```

- Same structure already handled by `preprocessKatex()` in `src/lib/sanitize.ts` (used for
  Perplexity/ChatGPT/Claude): `span.katex-display` → `div[data-math]`, `span.katex` →
  `span[data-math]`, then converted by the existing `mathBlock` / `mathInline` Turndown rules.
- LaTeX source is in `annotation[encoding="application/x-tex"]`.
- Observed on `/chat/8013b90c-…`: 11 display formulas, none in user messages; not under
  `content-visibility`.

**Inline math** (verified on `/chat/776397b1-…`) appears in **two forms**, depending on how
the message was rendered:

1. **Raw text** — on page load (and still after 15 s), the `$$…$$` delimiters stay as plain
   text inside the paragraph; no KaTeX element exists:
   ```html
   <p>Sottrai 3 da entrambi i membri: $$2x + 3 - 3 = 9 - 3$$<br>quindi $$2x = 6$$</p>
   <p>Dividi entrambi i membri per 2: $$x = \frac{6}{2}$$</p>
   ```
2. **KaTeX inline** — after a client-side re-render (observed after switching the version of
   an earlier response, §3.10), the same formulas become bare `span.katex` inside the `<p>`,
   `math` without `display` attribute, TeX in the annotation (`2x = 6`, `x = \frac{6}{2}`, …).

The extractor must handle both forms and produce the same output (see FR-009).

### 3.10 Header label, response versions, empty responses

- **Header label**: when the user picks a model, the header shows the model name instead of
  "Merlin" (e.g. "GPT 6 Luna", "Claude Sonnet 5.5"); the icon is
  `img[alt="<model-id> ai model's icon"]` (e.g. `gpt-6-luna ai model's icon`). Role detection
  and icon exclusion must not depend on the "Merlin" text.
- **Response versions**: an assistant message may show a pager
  (`div.select-none.items-center.text-sm` → `‹ 1 / 2 ›`). Each version is a **branch**:
  switching to 2/2 replaced the message id and removed **all following messages** (8 → 2
  articles); switching back restored them. The DOM only contains the displayed branch.
- **Empty responses**: in the sample, both versions of the first response had an empty body
  (all `.chat-reply-markdown` empty).

### 3.11 Web-search citations

- Inline citations are `<sup class="not-prose citation-shimmer …">` elements that are **empty**
  (no text, no link), after the cited list item. No `a[href]` exists in the response body.
- The sources (title, domain, URL) appear only inside the agent steps (header button
  `<model> ›` → `h3 > button "Searched the web"` → list of `a[href]`), and are not linked to
  the individual `<sup>` elements.

### 3.12 Project chats

- The URL stays `/chat/{uuid}`.
- The top bar breadcrumb `nav[aria-label="breadcrumb"]` shows
  `Projects › <project name> › <chat title>`:
  - `a[href="/chat/projects"]` → "Projects"
  - `a[href="/chat/projects/{projectUuid}"]` → project name (e.g. "Test")
  - last item (disabled link) → chat title
- For non-project chats the breadcrumb contains only the chat title.
- The project name is **not** exported (decision Q21); the breadcrumb is used only for the title.

### 3.8 Sponsored box (excluded)

Appears **only on responses received in the current session**. Verified by sending a new
question in `/chat/97cfdf53-…`: the box appeared below the new response, inside the assistant
`article`, after the action toolbar; **after a page reload the box was gone** (0 matches).

```html
<article data-message-id="…">
  <div class="flex items-center justify-between gap-2"> header </div>
  <div class="grid gap-1.5">
    <div> … response body … </div>
    <div class="z-10 flex …"> toolbar </div>
    <div>
      <div class="mt-3">
        <a class="block w-full rounded-2xl border …" target="_blank"
           rel="noopener noreferrer sponsored"
           href="https://api.trygravity.ai/track/click?p=…">
          <div …><img alt="" src="…"><span><span>Webz.io</span><span> · Sponsored</span></span></div>
          <p class="mt-3 line-clamp-2 …">Build powerful visualizations with …</p>
        </a>
      </div>
    </div>
  </div>
</article>
```

- Stable signals: `a[rel~="sponsored"]` and the `api.trygravity.ai` click-tracking host;
  " · Sponsored" label text. Only one box per page was observed (last response).
- It lies outside `.chat-reply-markdown`, but extraction must exclude it **explicitly** so it
  can never leak into the note (body text, links, or its advertiser logo as an image),
  even if Merlin later moves it inside the response body.

## 4. URL Structure

- Pattern: `https://www.getmerlin.in/chat/{uuid}`
- Example: `https://www.getmerlin.in/chat/ed96096b-c79b-46ee-bf25-83df2cad6093`
- Conversation ID: the UUID path segment.
- `document.title` is generic (`"Chat - Merlin AI"`); the real title is the last item of the
  top-bar breadcrumb (§3.12).

## 5. Functional Requirements

### FR-001 Platform registration

- Platform id `merlin`, label "Merlin", host `www.getmerlin.in` (strict match).
- Registered via `PLATFORM_REGISTRY` per [ADR-014](../adr/014-platform-registry-ssot.md);
  manifest `host_permissions` / `content_scripts.matches` updated.

### FR-002 Conversation ID

- From `/chat/{uuid}`. Fallback per existing extractor convention when absent.

### FR-003 Title

- From the last breadcrumb item (§3.12); fallback to the first user message,
  truncated to `MAX_CONVERSATION_TITLE_LENGTH`.
- The project name of project chats (§3.12) is **not** exported (no new frontmatter field).

### FR-004 Messages

- Iterate `article[data-message-id]` in DOM order; classify user/assistant (§3.2–3.3).
- User: plain text, multi-line preserved.
- Assistant: HTML of non-empty `.chat-reply-markdown`, sanitized (DOMPurify) and converted via
  Turndown. Exclude header, toolbars, credits, agent steps, craft cards, sponsored box,
  version pager.
- The assistant callout label is always **"Merlin"**, regardless of the model shown in the
  header (§3.10).
- **Versions**: only the branch currently displayed is exported (§3.10).
- **Empty responses** (no content) are skipped, as in the other extractors.
- **Citations**: the empty `<sup class="citation-shimmer">` markers are removed; no source list
  is exported (§3.11).

### FR-005 Images

- Capture each generated image (§3.4) in the content script as base64 via page `fetch`, using
  the shared `ImageMarkerCollector` and `g2o-image://` placeholder pipeline.
- Marker id must be stable (e.g. derived from `data-message-id` + index; final choice in design).
- Remove the "Generato con <model>" line.
- Existing guards apply (≤20 images/note, ≤10 MB/image), controlled by `enableImageExport`.

### FR-006 Artifacts (crafts)

- **Toggle**: craft export is gated by the existing `enableToolContent` setting ("Include
  tool/search results", default **off**), the same switch that gates Claude's Thinking/tool
  content (`src/content/extractors/claude.ts`). No new setting is added. When off, crafts are
  not read (no UI automation) and no craft reference is written, as Claude omits tool content.
- For each craft card, the extension **automates the UI**: click the card, select the "Code"
  tab, read the source (line-by-line rebuild, §3.5), then restore the previous panel state.
  (Claude's open-panel-only artifact capture is **not** adopted.)
- Only the version shown in the "Code" tab is exported; craft versions are not handled.
- Artifact metadata: original file name (card label), language (`data-language`), source text.
- File name in output: `{noteBaseName}-{originalName}` (e.g. `note-handshake-http.html`).
- **Duplicate names** within the same conversation: a suffix is added to keep every file
  (exact suffix format, e.g. `-2` before the extension, defined in design).
- Storage path: same folder as images (`imageVaultPath`).
- Note body: a **wikilink** (not embed) at the card position: `[[{noteBaseName}-{originalName}]]`.
- Per output:
  - **Obsidian**: file written to the vault under `imageVaultPath`.
  - **File download**: craft downloaded as separate file; body references the file name.
  - **Clipboard**: no file; reference removed/stripped like image placeholders.
- **Append mode**: aligned with images — craft placeholders are stripped and no craft file is
  written (as `stripImagePlaceholders()` in `src/background/obsidian-handlers.ts`).
- **Limits**: aligned with images — at most `MAX_IMAGES_PER_NOTE` (20) crafts per note and
  `MAX_IMAGE_SIZE_BYTES` (10 MB) per craft; excess or oversized crafts are skipped with a warning.
- A craft whose source cannot be read (timeout, panel not opening) must not abort the export:
  the note is saved and a warning is reported to the user.

### FR-007 Inline code

- Fenced blocks with language (§3.7); not saved as external files.

### FR-008 Sponsored content

- The sponsored box (§3.8) is ignored: no text, link, or image from it appears in the note,
  and its image is never captured by the image pipeline.
- Tests must cover a fixture of a freshly received response containing the box.

### FR-009 Tables and math

- Tables (§3.9) converted to Markdown tables with the **existing shared `tablesRule`**, which
  emits `---` for every column: column alignment is **not** preserved. The shared code in
  `src/content/markdown-rules.ts` is not modified. Actions toolbar excluded.
- KaTeX formulas (§3.9) exported from the TeX annotation in the same Markdown math format as
  the other platforms, reusing the existing KaTeX preprocessing and Turndown math rules.
- **Raw inline math** (§3.9, form 1): each `$$…$$` that appears inside running text is
  converted to **inline** math `$…$`, i.e. the same output as the KaTeX inline form (form 2).
  The TeX source must be kept verbatim (no Markdown escaping of `\`, `_`, `*`, …). This must
  be done inside the Merlin extractor so that the existing inline-math handling is reused
  unchanged (e.g. by turning the raw text into the same markup the existing KaTeX
  preprocessing already accepts); shared math code is not modified.

## 6. Non-Functional Requirements

- **Security**: strict hostname match; `https://www.getmerlin.in` in `ALLOWED_ORIGINS` (derived
  from registry); all assistant HTML through `sanitizeHtml()`; artifact file names validated
  against path traversal (`containsPathTraversal()`) and sanitized for filesystem-unsafe chars.
- **Resilience**: fallback selectors per element; partial extraction emits warnings.
- **Non-intrusiveness**: the craft automation must leave the page in a usable state and not
  trigger edits (never click the "Edit" tab, never use "Regenerate").
- **Consistency**: extend `BaseExtractor`; same frontmatter/callout format as other platforms.
- **Minimal impact on existing code**: keep the existing code as intact as possible. Reuse
  existing mechanisms (settings, frontmatter fields, sanitization, Turndown rules, image
  pipeline) unchanged; Merlin-specific behaviour lives in the Merlin extractor. Changes to
  shared code are limited to what is strictly required (platform registration, the new
  artifact pipeline, the `enableToolContent` sublabel) and must not alter the output of the
  other platforms.
- **E2E**: Merlin selectors added to the selector-validation suite and baselines (ADR-016/031).
